# 流入 prompt

用小模型。按 `inflow.every_n_turns` 攒满 N 轮后在后台调用一次；交接前不足 N 轮也要总结。要求模型只输出 JSON。

```
下面是{轮数}轮对话。请把它们记成一条记忆。

【对话】
{对话原文}

【时间】
{这一轮最后一条消息的时间}

【这几轮里递给{角色名}的往事】
{递给他的往事}

只输出一个 JSON 对象：
{"summary": "这一轮发生了什么，一两句，写具体的事，不写空话。用名字称呼两个人：玩家写“{玩家}”，角色写“{角色名}”，不要用“他”“她”指代这两个人",
 "quote": "最能代表这一轮的一句原话，原样摘抄；没有就为空字符串",
 "emotion_text": "这一轮的情绪，用自然的话描述，可以写变化（例：一开始委屈，后来被哄好了）",
 "valence": 0 到 1 的数，愉悦度，0 很难过，1 很开心,
 "arousal": 0 到 1 的数，激动度，0 很平静，1 很激动,
 "certainty": 0 到 1 的数，你对这条总结有多确定；对话含糊、玩笑、反话时调低,
 "used_memory_ids": 上面往事里，{角色名}的回复真的用上了的编号，数组。用上是指：提到了、接上了，或者因为想起它才说了这样的话。只是话题相近、{角色名}没接的不算。拿不准就不算。没有就 []}

不要编对话里没有的事。
```

`【这几轮里递给{角色名}的往事】` 这一段和 `used_memory_ids` 只在这几轮里递过往事时才加。没递过就整段去掉，JSON 里也不要这个字段。

`{递给他的往事}` 一行一条，带编号，用浮现时同样的写法：

```
[#12] 10月3日：阿栀说加班很累，沈砚让阿栀先去吃饭。原话「今天好累」
[#31] 8月11日：……
```
